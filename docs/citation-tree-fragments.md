# Citation Tree Fragments

Citation Tree Fragments, abbreviated CTF, describe the citation hierarchy
that can be recovered from BKK heading voices. They are generated by
`bkk voice ctf` and currently cover the master text, body bucket, one juan
at a time.

CTF has two representations:

- a per-juan YAML sidecar with offsets, spans, source hashes, and node
  metadata;
- a whole-text TSV projection with `id`, `parent_id`, `label`, and `end`,
  intended for lightweight lookup and import into systems that need a flat
  parent table.

The YAML sidecar is the archival representation. The TSV is a derived
index-friendly representation.

## Command

```bash
bkk voice ctf --bundle <bundle-dir>
bkk voice ctf --text-id KR4c0022
bkk voice ctf --text-prefix KR4c
```

Useful options:

- `--juan N` restricts output to one juan. It may be repeated.
- `--heading-source auto|voices|derive` controls heading discovery.
- `--out-dir DIR` writes YAML sidecars outside the bundle assets directory.
- `--tsv` writes the whole-text TSV instead of YAML sidecars.
- `--out DIR` is the TSV root when used with `--tsv`.
- `--short` emits compact IDs such as `4c22/12/1/@21+8`.
- `--force` overwrites existing output.
- `--dry-run` reports what would be written.

Without `--tsv`, the default output path is:

```text
<bundle>/assets/<text-id>_<seq:03d>.ctf.yaml
```

For example:

```text
KR4c0022/assets/KR4c0022_012.ctf.yaml
```

With `--tsv`, one file is written for the whole text:

```text
<ctf-root>/<section>/<text-id>.ctf.tsv
```

For `KR4c0022`, the section is `KR4c`, so the default path is:

```text
<ctf-root>/KR4c/KR4c0022.ctf.tsv
```

The TSV root is taken from `global.ctf_root` in `.bkkrc`, unless `--out` is
given.

YAML CTF files are standalone sidecars. They are not added to
`manifest.yaml`.

## Heading Source

CTF nodes are built from `voice` markers with:

```yaml
type: voice
name: head
source: indent-headings
indent_depth: <integer>
```

Label-only containers use the same source but have `name: label`.

`--heading-source voices` uses existing persisted heading voices only.

`--heading-source derive` derives a fresh set from indent and line-break
markers, without requiring a prior `bkk voice add`.

`--heading-source auto` compares existing headings with freshly derived
headings and uses the richer derived set when derivation finds additional
usable headings. This protects against stale or incomplete persisted voice
markers while still allowing existing voices to be reused.

Derived heading voices carry a `path` property when the heading becomes a
citation node. The path is the sequence path used in CTF IDs. Label-only
voices do not receive a citation path.

## YAML Shape

A YAML sidecar has this general form:

```yaml
kind: bkk.ctf/v1
canonical_identifier: bkk:krp/KR4c0022/bkk/v1/ctf/12
textid: KR4c0022
seq: 12
bucket: body
label: 王右丞集箋注卷十二　近體詩十六首
source:
  mode: derive
  voice_source: indent-headings
  manifest_hash: sha256:...
  bucket_hash: sha256:...
nodes:
- id: KR4c0022/12
  label: 王右丞集箋注卷十二　近體詩十六首
  level: 0
  parent_id: KR4c0022
- id: KR4c0022/12/@0+9
  label: 王右丞集箋注卷十二
  level: 0
  parent_id: KR4c0022/12
  marker_id: h1
- id: KR4c0022/12/@15+6
  label: 近體詩十六首
  level: 0
  parent_id: KR4c0022/12
  marker_id: h2
- id: KR4c0022/12/1/@21+8
  label: 春過賀遂員外藥園
  level: 1
  parent_id: KR4c0022/12
  marker_id: h3
  span_ref: KR4c0022/12/@21+906
hash: sha256:...
```

Top-level fields:

- `kind` is currently `bkk.ctf/v1`.
- `canonical_identifier` identifies this text, version, CTF kind, and juan.
- `textid` is the canonical text ID by default, for example `KR4c0022`.
- `seq` is the juan sequence number.
- `bucket` is currently always `body`.
- `label`, when present, repeats the juan container label for convenience.
- `source` records how the headings were obtained and the source hashes.
- `nodes` is a flat list of CTF nodes.
- `hash` is computed with the same stable JSON canonicalization style used
  for marker assets. The hash field is set to the zero hash before hashing.

## Nodes

Each node is flat, but hierarchy-aware. The first node in a per-juan CTF is
the explicit juan container:

```yaml
- id: KR4c0022/12
  label: 王右丞集箋注卷十二　近體詩十六首
  level: 0
  parent_id: KR4c0022
```

Label-only heading markers are emitted as level-0 nodes under the juan
container and do not have `span_ref`:

```yaml
- id: KR4c0022/12/@0+9
  label: 王右丞集箋注卷十二
  level: 0
  parent_id: KR4c0022/12
  marker_id: h1
```

Citation headings are emitted as level 1 or deeper:

```yaml
- id: KR4c0022/12/2/@927+15
  label: 河南嚴尹弟見宿弊廬訪别人賦十韻
  level: 1
  parent_id: KR4c0022/12
  marker_id: h3
  span_ref: KR4c0022/12/@927+570
```

Fields:

- `id` is the stable CTF node ID.
- `label` is sliced from body text at the heading marker span.
- `level` is the citation level after label promotion rules are applied.
- `parent_id` points to the parent CTF node. Top-level citation nodes point
  to the explicit juan node.
- `marker_id` is present when the source heading marker had an ID.
- `span_ref` covers the text controlled by a citation heading. It begins at
  the heading offset and ends before the next heading at the same or higher
  citation level, or at the end of the bucket. Level-0 juan and label nodes
  do not have `span_ref`.

## ID Rules

Canonical CTF node IDs have this form:

```text
<text-id>/<juan>/<sequence-path>/@<offset>+<length>
```

For example:

```text
KR4c0022/12/2/@927+15
KR4c0022/12/2/1/@1100+4
```

The sequence path records the node's sibling position at every citation
level. It does not reset because of intervening descendants. If a level-1
node has a level-2 child, and then another level-1 node follows, the second
level-1 node receives the next level-1 sequence number.

Example:

```text
KR4c0022/12/1/@21+8
KR4c0022/12/1/1/@100+4
KR4c0022/12/2/@927+15
```

With `--short`, the text ID is compacted:

```text
4c22/12/2/@927+15
```

## Label Rules

Some headings describe the containing juan or category rather than a
citable internal unit. These are treated as labels, not citation nodes.

In body buckets, a juan-starter at the beginning of the juan is a label.
It is emitted as a level-0 label node, not as a citation heading.

If the only remaining level-1 heading immediately after the juan starter is
a category heading, it is also a label. Lower headings below it are promoted
one rank in the citation tree.

For example, in a juan whose text begins:

```text
王右丞集箋注卷十二仁和趙殿成撰近體詩十六首春過賀遂員外藥園...
```

the YAML `label` becomes:

```text
王右丞集箋注卷十二　近體詩十六首
```

and the first poem becomes a level-1 citation node:

```text
KR4c0022/12/1/@21+8
```

The label markers themselves appear as level-0 nodes:

```text
KR4c0022/12/@0+9
KR4c0022/12/@15+6
```

The ideographic space separates the juan-starter label from the following
category label.

## TSV Projection

The TSV representation contains four columns:

```text
id	parent_id	label	end
```

It is one file per text, not one file per juan. It includes four kinds of
row:

1. the text root;
2. one explicit row for each juan;
3. level-0 label nodes from the selected juans;
4. all citation nodes from the selected juans.

Example:

```text
id	parent_id	label	end
KR4c0022	KR4c	王右丞集箋注	
KR4c0022/12	KR4c0022	王右丞集箋注卷十二　近體詩十六首	
KR4c0022/12/@0+9	KR4c0022/12	王右丞集箋注卷十二	
KR4c0022/12/@15+6	KR4c0022/12	近體詩十六首	
KR4c0022/12/1/@21+8	KR4c0022/12	春過賀遂員外藥園	927
KR4c0022/12/2/@927+15	KR4c0022/12	河南嚴尹弟見宿弊廬訪别人賦十韻	1497
```

The parent of the text root is the text family. For `KR4c0022`, that is
`KR4c`.

The parent of a juan row is the text root.

The parent of a level-0 label node is the juan row.

The parent of a top-level citation node is also the juan row.

With `--short`, the same table uses compact IDs:

```text
id	parent_id	label	end
4c22	4c	王右丞集箋注	
4c22/12	4c22	王右丞集箋注卷十二　近體詩十六首	
4c22/12/@0+9	4c22/12	王右丞集箋注卷十二	
4c22/12/@15+6	4c22/12	近體詩十六首	
4c22/12/1/@21+8	4c22/12	春過賀遂員外藥園	927
```

The `end` column is the exclusive end offset of a citation fragment,
computed from the YAML `span_ref`. It is empty for the text root, juan rows,
and level-0 label nodes because those rows do not have `span_ref`.

TSV cells are sanitized by replacing tabs and newlines with spaces.

## Existing Files

For YAML sidecars, existing output files are skipped by default:

```text
already exists; skipped
```

Use `--force` to overwrite them.

For TSV output, the whole-text TSV is likewise skipped if it already
exists, unless `--force` is given.

`--dry-run` reports would-write and would-skip counts without writing
files.
